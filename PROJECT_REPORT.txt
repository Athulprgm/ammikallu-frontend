3. BUGS / CORRECTNESS ISSUES (remaining)
--------------------------------------------------------------------------------
B1. Side effect still inside a state updater — AppContext.jsx, toggleWishlist()
    --------------------------------------------------------------------------
    showToast(...) is called INSIDE the setWishlist(prev => { ... }) updater.
    This is the exact anti-pattern fixed for the cart (Bug #2 in the first pass).
    React StrictMode double-invokes updaters in dev, and updaters must be pure.
    -> Compute `exists` from current `wishlist` before calling setWishlist, then
       show the toast outside — mirror the addToCart pattern.

B2. Inconsistent / duplicated asset folders, one with a space in the name
    --------------------------------------------------------------------------
    Both variants of each product folder exist AND are referenced by different
    code, so they cannot simply be deleted without updating callers:
      seedData.js         -> '/manjal-podi/…'   and '/mulakupodi/…'
      CustomerHome.jsx    -> "/manjal podi/select product-manjalpodi.png"
                             "/mulaku-podi/select product-mulakupodi.png"
    Folders: manjal podi (9.5M) ≈ manjal-podi (7.6M) · mulakupodi (9.6M) ≈
    mulaku-podi (9.6M). Note the SPACE inside "manjal podi" / "kurumulaku podi"
    (URL-encoded to %20 — fragile on deploy/CDN).
    -> Choose ONE canonical naming scheme (hyphen, no spaces), consolidate the
       folders, delete the duplicates, and update every reference. Reclaims ~19 MB.

B3. Stale closure in addReview() — AppContext.jsx
    --------------------------------------------------------------------------
    The setProducts updater averages ratings using `reviews` captured at render
    time (before the new review landed), plus `newRev`. It works for one add, but
    is order-dependent under rapid adds. -> Compute from the functional state or
    derive ratings in a selector instead of mutating product state.

B4. Coupon not re-validated at checkout
    --------------------------------------------------------------------------
    applyCouponCode checks minOrder against the cart, but the cart can change
    afterwards and the discount is recomputed with the same coupon. -> Re-validate
    on checkout (or drop the coupon when the cart falls below the minimum).

B5. addAddress() fires two setAddresses calls
    --------------------------------------------------------------------------
    One to clear existing defaults, one to append. Two sequential updaters on the
    same slice — fold into a single functional update for clarity and atomicity.

B6. Hardcoded placeholder identity in placeOrder()
    --------------------------------------------------------------------------
    Fallbacks 'Athul Krishna' / '+91 98765 43210' are written into real orders when
    the form is blank. -> Require the fields (or use an empty-string placeholder).

B7. notifications are not persisted
    --------------------------------------------------------------------------
    Orders/wishlist/cart survive refresh but the notification feed resets to the
    single seeded welcome item. Minor, but inconsistent with the rest.


4. PERFORMANCE
--------------------------------------------------------------------------------
P1. Hero = 240-frame JPEG sequence (public/bg 15 MB)
    --------------------------------------------------------------------------
    HeroSection.jsx builds `/bg/ezgif-frame-001.jpg … -240.jpg` and steps through
    them. That is up to 240 image requests / decodes for the hero alone.
    -> Replace with a single muted looping <video> (webm + mp4 fallback), a short
       sprite sheet, or cap the sequence (~40–60 frames) and compress. Biggest
       single win for first-load and mobile.

P2. Oversized raster assets on a runtime path
    --------------------------------------------------------------------------
    logo.png       1.8 MB  (also used as <link rel="icon"> — a 1.8 MB favicon!)
    image copy.png 1.8 MB  (unused)
    image.png      1.5 MB  (unused)
    Product PNGs   1.7–2.6 MB each.
    -> Convert to WebP/AVIF, resize to the max rendered size, and replace the
       favicon with the (already present but unused) favicon.svg or a small PNG.

P3. Almost no lazy-loading
    --------------------------------------------------------------------------
    Only 3 loading="lazy" attributes in the whole app (2 in CustomerHome, 1 in
    ProductCard). -> Lazy-load all below-the-fold images; give hero frames
       width/height to avoid layout shift; add decoding="async".

P4. No code-splitting
    --------------------------------------------------------------------------
    All 6 views ship in one 325 KB chunk. -> React.lazy + Suspense per view
       (SellerPortal/AdminConsole need not load for customers).

P5. ~19 MB of duplicate folders + ~7 MB of unused images (see 5 below)

NOTE: React.lazy and true routing go together — see A1.

6. ARCHITECTURE & DEVELOPER EXPERIENCE
--------------------------------------------------------------------------------
A1. No routing
    Current view = string in context. Consequences: no deep links / shareable URLs,
    browser Back/Forward don't work, refresh always lands on Home, per-route code
    splitting and SEO are impossible.
    -> Add react-router-dom with real routes (/ , /shop , /shop/:category ,
       /seller/:id , /account , /seller , /admin) and React.lazy per route.

A2. AppContext.jsx is a "god context" (~503 lines)
    Mixes navigation, entities (products/sellers/categories/reviews), cart,
    coupons, orders, notifications, addresses, and admin actions. Every consumer
    re-renders on any change.
    -> Split into focused providers/hooks (useCart, useCatalog, useAuth/view,
       useOrders) or adopt a small store (Zustand). This also fixes the
       stale-closure risks in B3/B5.

A3. No quality tooling
    No ESLint, no Prettier, no tests, no CI. -> Add eslint + prettier +
       vite-plugin-eslint, at least smoke tests, and a CI build check.

A4. Housekeeping
    package.json name -> "ammikallu-frontend". README is a single line. Commit
    messages are all "fix" — conventional commits would help.
    public/robots.txt exists but there is no sitemap.xml.

A5. SEO / PWA gaps in index.html
    - No <link rel="manifest"> even though public/site.webmanifest exists.
    - Missing og:image, og:url, og:type, twitter:card, canonical.
    - <html lang> is set (good) but no theme-color meta.
    -> Add the manifest link, an og:image (use a compressed hero still), and the
       twitter card tags.

A6. Accessibility (partly fixed)
    Modals now trap focus / close on Escape. ProductCard is keyboard-accessible
    (role=button, tabIndex, Enter). Audit the remaining clickable divs and icon
    buttons for labels and keyboard reach, and verify color contrast on the
    gold-on-cream and muted-grey text.
